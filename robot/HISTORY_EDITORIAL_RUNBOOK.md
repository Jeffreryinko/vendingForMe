# 역사 편집 이야기 만드는 법

역사 탭의 ‘오늘의 사건·시리즈’에 나오는 이야기는 로봇이 자동으로 만들지 않습니다. 사람(또는 Claude에게 부탁)이 출처를 확인하며 한 편씩 씁니다. 한 번 쓰면 유지비는 0원입니다.

## 파일

| 파일 | 내용 |
|---|---|
| `data/history/editorial/episodes/{id}.json` | 이야기 한 편: 장면·선택·결과·출처·다음 질문·수정 이력 |
| `data/history/editorial/index.json` | 코너(programs), 기분(moods), 시리즈(series), 대표작 편성(featured), 이야기 목록(자동) |
| `robot/history_editorial.py` | 검사 + 목록 다시 만들기. 이야기를 고치거나 더한 뒤 반드시 실행 |
| `assets/history-player.js` · `.css` | 공통 플레이어 (장면 부품을 조합해서 보여 줌) |

## 한 편 추가하기

1. **소재 한 줄**: 상황 한 문장, 주요 의문, 어울리는 코너(then·docs·rumor·clock·day·short).
2. **근거 확인**: 사건 개요와 핵심 반전을 출처에서 직접 확인. 출처마다 ‘뒷받침하는 것(supports)’을 적는다.
3. **기획 판정**: 근거가 제목을 지지하는지. 지지하지 않으면 제목을 바꾼다.
4. **대본**: 장면마다 표시(mark)를 단다.
   - `fact` 기록: 문장 끝에 `[1]`처럼 출처 번호
   - `interp` 해석, `recon` 연출상 재구성(‘당신은…’, 꾸민 문서), `hypo` 가정, `lore` 전승
5. **검사**: `python3 robot/history_editorial.py`. 틀리면 목록을 안 바꾸고 이유를 보여 줌.
6. **폰에서 확인** 후 `sw.js`의 VER를 올리고 배포.
7. **수정할 때**: `ver`를 고친 날로, `log`에 `{"v": "날짜", "what": "무엇을 고쳤나"}`를 더한다. id(주소)는 바꾸지 않는다.

## 장면 종류

`intro` 도입 · `narr` 서술 · `doc` 펼쳐 보는 자료(items) · `tabs` 지역 비교(tabs) · `rel` 관계([[A, 관계, B]] 3~4줄) · `choice` 선택(q, opts 2~4개, skip) · `info` 새 정보 · `result` 결과(**한 편에 꼭 하나**, 여기 닿으면 ‘다 봄’) · `meaning` 여운

- 선택 응답에서 `{c1}`이라고 쓰면, 그 장면에서 고른 것의 이름이 들어간다. “처음에는 ‘{c1}’ 쪽을 고르셨고”처럼 조사가 안 붙게 쓴다.
- `next`(다음 질문)는 3개까지: `{"ep": id}` 다른 이야기, `{"page": "원문 제목"}` 원문 자료, `{"xm": "sync", "se": 시대번호, "from": 연도}` 나란히 보기.

## 지킬 것 (기획안 13~16장)

- 제목에 ‘충격·소름·역대급’ 같은 말로 재미를 대신하지 않는다.
- 다른 선택의 결말을 지어내지 않는다. ‘이 선택에서 검토할 위험’으로만 쓴다.
- 결과에서 하나의 사건이 전쟁·역사를 결정했다고 단정하지 않는다. 반대 평가도 함께 쓴다.
- 실제 피해자의 고통을 웃음거리로 쓰지 않는다.
- 실제 집계 없이 “87%가 속았습니다” 같은 숫자를 쓰지 않는다.
- 소문을 반박하는 이야기도 근거를 따진다. 반박도 또 하나의 소문일 수 있다.
- 지역·주체 균형을 본다. 전쟁·유럽·유명 남성만으로 채우지 않는다.
